# Owner Property v3-clean

Чистая кодовая база закрытой PWA для владельца 2–3 коммерческих объектов. Ветка восстановлена из целой monolithic v1.0 и больше не зависит от `baseline-*`, `.b64`, overlays или patch-chain.

## Ежедневная работа · 3.8.0

- **Сегодня** — срочные дела владельца или назначенные сотруднику задания.
- **Объекты** — откройте карточку: задания, арендаторы, осмотры, оборудование, показатели и расходы выбранного объекта.
- **Задания** — единый список обращений и работ, поиск, открытые/выполненные, фильтр «Назначенные мне».
- **Настройки / Профиль** — дополнительные разделы. Только владелец управляет сотрудниками и паролями.

Для сотрудника: открыть задание → «Начать работу» → «Отправить фотоотчёт». Дополнительные поля форм раскрываются по необходимости. Архивирование и изменение объекта находятся в «Сведениях об объекте и управлении» внутри его карточки. На экранах объекта «Все объекты» снимает фильтр.

## Удобство и фотографии · 3.9.0

На главном экране владельца есть группы «Сегодня», «Просрочено» и «Без исполнителя», включая обычные назначенные задания на сегодня. Списки обновляются при возвращении в приложение и раз в минуту; открытая форма сохраняется. Закрытие задания, открытого из объекта, возвращает карточку объекта с прежней прокруткой. Срок нового задания виден сразу, доступны кнопки «Сегодня», «Завтра» и «Через неделю».

Фотографии JPG, PNG и WEBP показываются перед отправкой. Повторный выбор добавляет снимки к выбранным; каждый можно убрать отдельно. Крупные фото уменьшаются в браузере до 2400 пикселей по длинной стороне и лимита 4 МБ. Исходный файл — до 40 МБ, до 5 фото в одном поле; HEIC нужно предварительно сохранить в JPEG. Черновик хранит выбранные файлы на устройстве. Сохранённые фото удаляет только владелец; действие отражается в истории. Последнее фото отчёта/дефекта и минимум три внешних фото осмотра защищены. Осмотр проходит через три шага: объект и фото, помещения, проверка перед отправкой.

Для проверки интерфейса в установленном Chromium: `node tests/browser.cjs`, `node tests/ux-photos-browser.cjs` и `node tests/session-browser.cjs`. Пути к Playwright и браузеру можно задать через `PLAYWRIGHT_MODULE` и `BROWSER_EXECUTABLE`. Проверки работают с временной базой, вне данных приложения.

## Сохранение входа · 3.8.1

Вход сохраняется на 30 дней бездействия и продлевается при использовании. Закрытие приложения и обычное обновление сервиса не сбрасывают сессию. «Выйти», смена пароля и отключение сотрудника прекращают соответствующие сессии. При ошибке связи на запуске доступен повтор загрузки без формы входа. После перехода со старой версии потребуется один повторный вход.

## Возможности

- объекты: создание, редактирование, архивирование, восстановление и защищённое удаление пустой архивной карточки;
- арендаторы и помещения без хранения договоров;
- проблемы, сроки, ответственные, фото и фотоотчёты;
- осмотры объекта и арендаторов, маршрутизация найденных проблем;
- сотрудники, роли, доступ по объектам, отключение сессий, сброс пароля;
- оборудование, показатели и расходы;
- приватные фото, CSRF, HttpOnly/SameSite cookies, rate-limit входа;
- SQLite WAL, backup и PWA.

## Чистый production start

Репозиторий не содержит демо-объектов, демо-арендаторов, тестовых сотрудников, тестовых логинов или паролей. При первом запуске создаётся только владелец из переменных `OWNER_LOGIN` и `OWNER_PASSWORD`.

## Проверка

```bash
npm run check
OWNER_LOGIN=owner OWNER_PASSWORD='strong-password' npm test
```

## Запуск на сервере

```bash
sudo ./install.sh
```

По умолчанию Caddy публикует приложение на порту `8787`. Healthcheck:

```bash
curl http://127.0.0.1:8787/healthz
```

Ожидаемая версия: `3.0.0`.

## Важно

`data/*.db`, `.env`, `private_uploads/`, `backups/` и `node_modules/` исключены из Git. Договоры и произвольные конфиденциальные документы приложением не хранятся.
