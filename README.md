# Owner Property Management PWA — v2.0

Закрытая личная PWA-система управления эксплуатацией собственных объектов недвижимости.

Репозиторий: `Deels2024/upravlenie`.

## Что входит в v2.0

- объекты: создание, редактирование, архив, восстановление, безопасное удаление;
- арендаторы и помещения;
- проблемы, ответственные, сроки и статусы;
- фотографии проблемы и фотоотчёты **До / После**;
- дата, время и подпись исполнителя;
- подтверждение результата арендатором или возврат проблемы в работу;
- еженедельные осмотры объектов с 3–4 фотографиями фасада и проверкой арендаторов;
- автоматическое создание проблем из осмотра и маршрутизация ответственным;
- сотрудники, роли, права и доступ к конкретным объектам;
- мгновенная блокировка сессий отключённого сотрудника;
- оборудование и техническое обслуживание;
- электричество, вода, тепло и выявление аномалий;
- эксплуатационные расходы и ₽/м²;
- мобильная PWA;
- закрытый backend-доступ к фотографиям и данным.

Документы аренды, банковские данные, паспортные данные и произвольное файловое хранилище намеренно не включены.

## Новое в v2.0

### Health Score объекта

Для каждого здания автоматически рассчитывается управленческий показатель состояния **0–100**. На него влияют:

- критические и просроченные проблемы;
- просроченное ТО;
- просроченные осмотры;
- аномалии потребления ресурсов;
- возвраты проблем арендаторами;
- повторяющиеся дефекты.

### Повторяющиеся проблемы

Система выявляет проблемы одной категории, которые повторялись по объекту/арендатору 3 и более раз за последние 180 дней.

### Обязательная 2FA владельца

В production владелец при первом входе должен настроить TOTP-2FA в Google Authenticator, Microsoft Authenticator или совместимом приложении.

Также выдаются 8 одноразовых recovery-кодов. Они показываются только при настройке 2FA.

### Проверяемый audit-log

Журнал административных и критичных действий связан HMAC hash-chain. Изменение старой записи обнаруживается системой.

### Проверяемые резервные копии

Backup проходит:

- SQLite `PRAGMA quick_check`;
- SHA-256 проверку файлов;
- создание `MANIFEST.json`;
- копирование во второе зеркало `backup-mirror`;
- отдельную повторную проверку через `scripts/verify-backup.js`.

### Чистый production

Новая установка v2.0 стартует с пустым портфелем. Тестовые объекты и арендаторы в production автоматически не создаются.

## Установка на Ubuntu / Debian

```bash
git clone https://github.com/Deels2024/upravlenie.git
cd upravlenie
chmod +x install.sh
sudo ./install.sh
```

Корневой установщик:

1. собирает единый модульный baseline v2.0 из `v2-source/`;
2. проверяет ZIP по SHA-256;
3. только после успешной проверки распаковывает новую версию;
4. сохраняет существующие `.env` и Caddy/HTTPS-настройки;
5. запускает production installer v2.0;
6. сохраняет прежнее Docker Compose project name `property-owner-pwa`, поэтому существующие volumes с базой и фотографиями продолжают использоваться.

Контрольная сумма baseline v2.0:

`19fbf4fe1e6eca3fefc86b66a34395f6b1b9e19d5c7c1b6bad99d4abc8862717`

Порядок частей зафиксирован в `v2-source/MANIFEST.txt` и в `install.sh`.

## Обновление существующего сервера

```bash
cd upravlenie
git pull
sudo ./install.sh
```

При переходе с v1.x сохраняются:

- существующая SQLite-база в Docker volume;
- фотографии в Docker volume;
- пароль владельца и секреты из `.env`;
- доменная/HTTPS-конфигурация Caddy.

Предыдущая кодовая версия временно сохраняется в `app/property-owner-pwa.previous`.

## HTTPS

После направления домена на IP сервера:

```bash
cd app/property-owner-pwa
sudo ./enable-https.sh example.ru
```

## Backup

Ручной backup:

```bash
cd app/property-owner-pwa
sudo ./backup-now.sh
```

Проверка существующей резервной копии:

```bash
docker compose run --rm backup node scripts/verify-backup.js /app/backups/ИМЯ_BACKUP
```

## Аварийный сброс 2FA владельца

Используйте только при потере и Authenticator, и recovery-кодов:

```bash
cd app/property-owner-pwa
sudo docker compose exec app node scripts/reset-owner-2fa.js
```

Операция фиксируется в audit-log.

## Безопасность

- самостоятельной публичной регистрации нет;
- роли и разрешения проверяются на backend;
- арендатор получает только свои данные;
- база не публикуется в интернет отдельным портом;
- фотографии хранятся приватно и отдаются после авторизации;
- PWA не кэширует чувствительные API-данные;
- production требует 2FA владельца;
- административные события защищены hash-chain;
- обновление кода останавливается до замены рабочей версии, если SHA-256 baseline не совпал.

Старые каталоги v1.x могут оставаться в истории/дереве репозитория как legacy-артефакты, но **текущий `install.sh` их больше не использует**. Единственный источник устанавливаемой версии — baseline v2.0 в `v2-source/`.
