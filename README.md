# Owner Property Management PWA — v2.4

Закрытая PWA-система управления собственными объектами недвижимости.

## v2.4 — надёжная работа на объекте

### Офлайн-осмотры

Если интернет пропал во время отправки готового осмотра, он сохраняется в локальной IndexedDB-очереди текущего браузера и автоматически отправляется после восстановления связи. На экране показывается состояние сети и количество неотправленных осмотров.

### Оптимизация фотографий

Перед отправкой эксплуатационные фотографии автоматически:

- уменьшаются максимум до 1920 px по длинной стороне;
- сжимаются до безопасного размера;
- перекодируются в JPEG;
- очищаются от EXIF-метаданных и GPS в отправляемой копии.

Серверные ограничения MIME и размера продолжают действовать отдельно.

### Контроль после ремонта

Для критических, высокоприоритетных и рискованных проблем после закрытия создаётся повторная проверка через 3, 7 или 14 дней. Контроль требует актуальную фотографию.

Если дефект повторился, система создаёт новую проблему высокого или критического приоритета и использует действующие правила маршрутизации. Контрольные проверки отображаются в Центре внимания и эксплуатационном календаре.

### Браузерные уведомления

Пользователь может явно включить локальные браузерные уведомления. Они работают, когда сайт или установленная PWA активны. Полноценный серверный Web Push с VAPID остаётся отдельным будущим этапом.

## Уже входит в систему

- управление активными и архивными объектами;
- единая карточка объекта;
- арендаторы и помещения;
- проблемы с фото До / После;
- еженедельные осмотры;
- оборудование и ТО;
- показатели ресурсов и расходы;
- Health Score, Центр внимания и календарь;
- роли и доступы;
- TOTP-2FA владельца;
- HMAC audit-log;
- проверяемые резервные копии.

## Обновление существующего сервера v2.3 → v2.4

```bash
cd upravlenie
git pull
sudo ./install.sh
```

Установщик v2.4:

1. проверяет наличие всех новых frontend/backend-модулей;
2. создаёт staging-копию уже установленной v2.3;
3. применяет v2.4 только к staging-копии;
4. запускает `npm run check` и отдельные syntax-check новых модулей;
5. проверяет версию и подключение backend/frontend;
6. только после успешных проверок заменяет рабочую кодовую директорию;
7. сохраняет предыдущую кодовую версию как `app/property-owner-pwa.previous`.

SQLite-база, фотографии, `.env`, 2FA и Caddy/HTTPS не пересоздаются и остаются в существующих Docker volumes/настройках.

## GitHub Actions

CI запускается на `main`, `release/**` и pull request в `main`. Он проверяет:

- синтаксис `install.sh` и `install-v2.4.sh`;
- наличие ключевой логики v2.4;
- syntax-check `field-tools.js`;
- syntax-check модулей media/offline/follow-up/notifications;
- manifest версии 2.4.

Полный runtime smoke-test v2.4 выполнялся отдельно на собранной тестовой копии. Текущий CI намеренно не собирает старую legacy baseline, потому что обычный production-апгрейд v2.4 теперь использует staging существующей v2.3.

## Важно про новую установку

Текущий корневой `install.sh` рассчитан на безопасное обновление уже установленной v2.3 до v2.4. Для полностью нового пустого сервера сначала будет подготовлена отдельная консолидированная clean baseline; старый повреждённый `v2-source` больше не должен использоваться как источник для fresh install.

## Безопасность офлайн-данных

Офлайн-очередь хранится в браузерном профиле конкретного устройства. На общих компьютерах используйте отдельные учётные записи ОС и блокировку экрана.
