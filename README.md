# Owner Property Management PWA — v2.5 Production Start

Закрытая PWA-система управления собственными объектами недвижимости.

## v2.5 — подготовка к реальной эксплуатации

Версия v2.5 переводит систему из тестового состояния в чистый production-режим.

При первом production-запуске после обновления система:

- создаёт safety-backup текущего состояния и SQLite-базы, если файл доступен;
- сохраняет владельца, его пароль, TOTP-2FA и recovery-данные;
- удаляет текущие объекты, арендаторов, проблемы, оборудование, показатели, расходы и осмотры;
- удаляет тестовых сотрудников и арендаторов, оставляя только владельца;
- очищает тестовые эксплуатационные фотографии;
- очищает планы осмотров, правила маршрутизации и уведомления;
- создаёт постоянный маркер `productionCleanStartAt`, поэтому автоматическая очистка выполняется только один раз.

После этого система открывается как чистая рабочая среда для внесения реальных объектов.

## Production UI

В v2.5 также убраны технические элементы тестовой версии:

- логин владельца больше не подставляется автоматически в поле входа;
- скрыта техническая подпись версии в бренде боковой панели;
- пример названия объекта заменён на нейтральный placeholder;
- новые реальные объекты больше не получают тестового пользователя `u-inspector`;
- фиксированные демонстрационные даты планов осмотров не используются.

## Что уже входит в систему

- добавление и редактирование объектов;
- архивирование и восстановление объектов;
- безвозвратное удаление пустой архивной карточки владельцем;
- единая карточка объекта;
- арендаторы и помещения;
- проблемы с фото До / После;
- подтверждение результата арендатором;
- еженедельные осмотры;
- оборудование и ТО;
- показатели ресурсов и расходы;
- Health Score, Центр внимания и календарь;
- офлайн-очередь осмотров;
- автоматическая оптимизация фотографий и удаление EXIF/GPS;
- контрольные проверки после серьёзных ремонтов;
- роли и доступы;
- TOTP-2FA владельца;
- HMAC audit-log;
- проверяемые резервные копии.

## Обновление сервера

```bash
cd upravlenie
git pull
sudo ./install.sh
```

Установщик v2.5 сначала создаёт staging-копию текущей рабочей версии, применяет изменения, выполняет `npm run check` и syntax-check новых модулей и только после этого переключает рабочую кодовую директорию.

## GitHub Actions и деплой

- CI запускается на `main`, `release/**` и pull request в `main`;
- проверяются `install.sh`, `install-v2.4.sh`, `install-v2.5.sh` и новые backend/frontend-модули;
- deploy автоматически запускается после push в `main`;
- целевой сервер: `5.183.191.139`;
- healthcheck: `http://127.0.0.1:8787/healthz` и внешний `http://5.183.191.139:8787/healthz`;
- успешный production-релиз должен вернуть версию `2.5.0`.

## Важно

Production-cleanup в v2.5 намеренно удаляет все текущие эксплуатационные записи при первом production-запуске. Перед очисткой создаётся резервная копия. Владелец и его 2FA сохраняются. После установки и появления реальных данных cleanup повторно не запускается.
