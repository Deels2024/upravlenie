# Owner Property Management PWA — v2.1

Закрытая личная PWA-система управления эксплуатацией собственных объектов недвижимости.

Репозиторий: `Deels2024/upravlenie`.

## Что нового в v2.1

v2.1 — визуальная полировка всего рабочего интерфейса без изменения эксплуатационной модели и данных.

- единая SVG-иконография вместо разрозненных символов и текстовых glyph-иконок;
- более крупная и читаемая типографика по всему ресурсу;
- единые размеры, веса и межстрочные интервалы заголовков, цифр, подписей и статусов;
- новый светлый premium UI: белые карточки, спокойные тени, аккуратные границы и более чистая сетка;
- заполненные цветные icon-chips для ключевых действий и показателей;
- переработаны sidebar, topbar, кнопки, фильтры, карточки, статусы, модальные окна и экран входа;
- одинаковый визуальный язык для объектов, проблем, осмотров, арендаторов, оборудования, показателей, расходов, сотрудников и безопасности;
- улучшена мобильная PWA-навигация и читаемость на небольших экранах;
- исправлено подключение CSS: вместо несуществующего `/app.css` теперь корректно подключаются `base.css`, `features.css` и новый `premium.css`;
- Service Worker переведён на новый cache `v2.1` и кэширует premium-стили;
- версия приложения и `/healthz` обновлены до `2.1.0`.

## Основные возможности

- объекты, Health Score, заполненность и ответственные;
- арендаторы и помещения;
- проблемы, сроки, исполнители, фото **До / После** и подтверждение арендатором;
- еженедельные осмотры и автоматическое создание проблем;
- сотрудники, роли, права и доступ к конкретным объектам;
- оборудование и ТО;
- электричество, вода, тепло и выявление аномалий;
- эксплуатационные расходы и ₽/м²;
- TOTP-2FA владельца и recovery-коды;
- HMAC hash-chain audit-log;
- проверяемые резервные копии;
- закрытая мобильная PWA.

Документы аренды, банковские данные, паспортные данные и произвольное файловое хранилище намеренно не включены.

## Установка на Ubuntu / Debian

```bash
git clone https://github.com/Deels2024/upravlenie.git
cd upravlenie
chmod +x install.sh
sudo ./install.sh
```

Установщик v2.1 работает безопасно:

1. восстанавливает проверенную модульную baseline v2.0 из `v2-source/`;
2. проверяет SHA-256 baseline v2.0;
3. собирает premium UI v2.1 из `patches/v2.1/`;
4. проверяет SHA-256 распакованного v2.1-патча;
5. применяет патч только во временной директории;
6. проверяет подключение `premium.css` и версию `2.1.0`;
7. при наличии Node запускает полный `npm run check`;
8. сохраняет существующие `.env` и Caddy/HTTPS-настройки;
9. только после всех проверок заменяет рабочий код и запускает приложение.

## Обновление существующего сервера

```bash
cd upravlenie
git pull
sudo ./install.sh
```

При обновлении сохраняются SQLite-база и фотографии в Docker volumes, пароль владельца и секреты из `.env`, а также Caddy/HTTPS-конфигурация. Предыдущая кодовая версия временно остаётся в `app/property-owner-pwa.previous`.

## HTTPS

```bash
cd app/property-owner-pwa
sudo ./enable-https.sh example.ru
```

## Backup

```bash
cd app/property-owner-pwa
sudo ./backup-now.sh
```

Проверка существующей копии:

```bash
docker compose run --rm backup node scripts/verify-backup.js /app/backups/ИМЯ_BACKUP
```

## Аварийный сброс 2FA владельца

```bash
cd app/property-owner-pwa
sudo docker compose exec app node scripts/reset-owner-2fa.js
```

Операция фиксируется в audit-log.

## Безопасность

- публичной регистрации нет;
- роли и разрешения проверяются на backend;
- арендатор получает только свои данные;
- база не публикуется отдельным интернет-портом;
- фотографии хранятся приватно и отдаются после авторизации;
- PWA не кэширует чувствительные API-данные;
- production требует 2FA владельца;
- административные события защищены hash-chain;
- обновление прекращается до замены рабочей версии, если любая контрольная сумма не совпадает.
