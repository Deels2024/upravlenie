# Проверка 6 сентября 2026

База: `recovery/v3-clean`, коммит `912b6f4c45350e5c60ed445142435520fb583c2e`.
Проверка выполнена локально на Node.js 24, с отдельной тестовой SQLite-базой.

## Подтверждено автоматическими проверками

- Запуск приложения, вход owner, создание, изменение, архивирование, восстановление и удаление пустого объекта.
- Создание сотрудников, вход по назначенному паролю, запрет админ-панели и управления учётными записями для сотрудников.
- Ограничение объектов по доступу, назначение задач только доступному активному исполнителю.
- Ошибка сохранения сотрудника не меняет его имя или логин частично.
- Совпадение имён сотрудников не открывает чужие задачи и фотографии.
- Итоговый фотоотчёт закрывает задачу; для арендатора переводит её в ожидание подтверждения. Прямое закрытие через изменение/создание задачи запрещено.
- Смена пароля и отключение сотрудника прекращают его сеанс.

Команды: `npm run check`, `npm test` — успешно. Добавлен отдельный workflow проверки для PR и ветки аудита.

## Другие исправления

- Удалена завершённая разовая миграция, которая при отсутствии маркера могла удалять реальные учётные записи сотрудников.
- Исправлена кодировка русских строк в серверных уведомлениях и истории.
- Мобильное меню открывает все разрешённые разделы; добавлена доступная на телефоне кнопка выхода.
- Таблица сотрудников на узком экране представлена карточками; исправлены цвета карточек задач и перенос длинных названий.
- Стили, блокировавшиеся политикой CSP, перенесены в CSS; диаграмма использует progress.
- Обновление service worker больше не принуждает открытые окна перезагружаться; кэш ограничен оболочкой приложения. Версия оболочки: 3.3.3.
- Каталог загрузок учитывает UPLOAD_DIR, что также изолирует фотографии тестов.

## Границы проверки

Рабочий сервер и реальные пользовательские данные не проверялись и не изменялись.
Визуальная проверка на телефоне/в браузере не завершена: загрузка Chromium недоступна в окружении. Не проверены камера телефона, установка PWA и поведение обновления на реальном устройстве.
Автотесты покрывают перечисленные сценарии, а не все разделы и возможные ошибки приложения.
На момент первоначального аудита изменения находились в отдельной ветке; они не появлялись в установленном приложении до слияния и обычного обновления проекта.

## Дополнение: удобство объектов, версия 3.4.0

- Поиск по названию, адресу и ответственному; фильтры внимания, просрочек и задач без исполнителя.
- Сортировка по срочности, названию или доле свободной площади; отметки просрочек в карточках.
- Все открытые задачи внутри объекта, выполненные — в сворачиваемой истории; создание задачи с уже выбранным объектом.
- Архив свёрнут, действие перемещения подписано «В архив», доступно рабочее примечание.
- Исправлено начальное отображение арендаторов при осмотре первого объекта; пустая форма не открывается без доступных объектов.
- Номер версии в меню; уведомление о новой версии при открытии, возвращении в приложение или обновлении данных. Перезагрузка выполняется по кнопке с подтверждением, если открыта форма.
- Перед деплоем выполняются проверки; после запуска сверяется файл версии, отданный приложением, с файлом выпуска.

Дополнительная локальная проверка DOM (LinkeDOM): поиск и фильтры меняют выдачу, карточка показывает более шести задач и историю, новая задача получает нужный объект, админ-панель отсутствует в меню сотрудника, отмена обновления сохраняет открытую форму. Это проверка поведения интерфейса без визуального рендеринга. HTTP-тест проверяет номер версии, отсутствие кэширования version.json и совпадение версий CSS/JS в оболочке.
