# Ежедневная работа — версия 3.6.0

## Владелец

1. В «Админ-панели» добавьте сотрудника, назначьте логин, пароль, роль и доступные объекты.
2. В «Объектах» используйте поиск и фильтры просрочек/задач без исполнителя. Из карточки можно создать задачу, провести осмотр, увидеть свободную площадь, расходы и историю.
3. В графике осмотров назначьте инспектора и дату. Напоминания о задачах и осмотрах появляются в колокольчике за день до срока, в день срока и после просрочки. Это уведомления внутри открытого приложения, не push на закрытом телефоне. Календарь напоминаний по умолчанию использует Europe/Moscow (переменная APP_TIME_ZONE).
4. В карточке объекта учтённые расходы и стоимость работ в задачах показаны отдельно: эти величины не складываются, чтобы не задвоить расходы. Существующий раздел агрегированных расходов не заменяет бухгалтерский учёт.
5. В админ-панели проверяйте дату последней резервной копии.

## Сотрудник

Войдите по выданным логину и паролю. Доступны только разрешённые разделы и объекты; админ-панель открывается только владельцу. Завершение задачи — через фотоотчёт; для обращения арендатора после него требуется подтверждение арендатора.

## Связь, черновики и обновления

- Черновики объекта, задачи, осмотра, фотоотчёта, арендатора и расходов сохраняются на устройстве. Текст и выбранные фотографии восстанавливаются в той же форме в течение 24 часов, в том числе после перезагрузки. Хранилище браузера может быть очищено системой или пользователем; это не замена серверной копии.
- В форме показано «Не отправлено», количество сохранённых фото или сообщение об ошибке локального хранения. При ошибке не закрывайте форму до отправки. Пароли не сохраняются; явный выход удаляет черновики пользователя. Другой пользователь не получает их в своих формах.
- Черновик не отправляется автоматически. Для отправки после восстановления связи нажмите кнопку сохранения. Для открытия приложения и загрузки рабочих данных требуется связь; полноценный автономный режим не реализован.
- Создание объекта, задачи, осмотра, фотоотчёта, арендатора и расходов защищено ключом повторного запроса от дублей при потере ответа сервера.
- После подтверждённого сохранения повторное нажатие заблокировано, даже если обновление списка не удалось.
- Версия видна в меню. Обновление открытой формы требует подтверждения.

## Резервные копии

В сценарии GitHub deployment включена отдельная служба `backup`: ежедневная копия, хранение 14 последних выпусков в Docker volume `upravlenie_backups`. Перед переключением версии также создаётся проверенная копия. Обычный `docker-compose.yml` использует тот же volume.

Копия включает SQLite-базу, пользователей с хешами паролей и приватные фотографии. Файл `.env` и инфраструктурные секреты нужно хранить отдельно. Копия завершается только после проверки целостности SQLite, контрольных сумм файлов и наличия фотографий, на которые ссылается база. Неудачная копия не считается готовой.

Проверка каталога копии (на машине с Node.js 22.16+ или 24):

```bash
node scripts/verify-backup.js /path/to/owner-property-BACKUP
```

Безопасное восстановление в НОВЫЙ пустой каталог:

```bash
node scripts/restore-backup.js /path/to/owner-property-BACKUP /path/to/empty-restored
```

Скрипт проверяет копию, создаёт `app.db` и `private_uploads`. При непустом целевом каталоге он отказывается работать. Для проверки восстановленного приложения используйте отдельный порт, DB_FILE и UPLOAD_DIR, указывающие на этот каталог, и нужные OWNER_LOGIN/OWNER_PASSWORD. Прежде чем переключать рабочую систему, проверьте вход, список объектов и фотографии.

Автотест действительно запускает второе приложение из восстановленной копии, проверяет объекты, сотрудников и содержимое фотографии; также проверяет отказ при повреждении копии и непустом каталоге назначения.

Копии находятся на том же сервере. Для защиты от потери всего сервера необходимо отдельно настроить копирование в другое хранилище; внешнее хранилище пока не подключено.

## Проверки

```bash
npm run check
npm test
```

Проверяются HTTP-сценарии, роли, назначения, напоминания, повторная отправка, фотоотчёты и восстановление. GitHub выполняет тесты на Node.js 22 и 24.

Для разработчика предусмотрен `tests/browser.cjs`. Он использует отдельную временную базу; требует установленного `playwright-core` и Chromium. Можно задать PLAYWRIGHT_MODULE и BROWSER_EXECUTABLE, а SCREENSHOT_DIR — для снимков. Проверены ширины 320, 390 и 1280, редактирование сотрудников и паролей, осмотр с фото, восстановление черновика, потеря ответа сервера и ограничение меню сотрудника. Реальная камера, системная установка PWA и Safari на физическом iPhone этой проверкой не охвачены.

## Назначения и расходы в 3.6.0

Список исполнителей учитывает права на просмотр и выполнение задач и доступ к объекту. В график можно назначить сотрудника с правами на просмотр и проведение осмотров на этом объекте, либо оставить «Не назначен». Проверка полей выполняется целиком до изменения графика. Глобальный маршрут действует только на объекты, доступные исполнителю.

В карточке арендатора появилась кнопка «Редактировать». Название, контакты, помещение и площадь меняются без потери истории; перенос между объектами этой формой не выполняется.

В разделе расходов владелец добавляет запись на объект и месяц, редактирует суммы по шести категориям, удаляет ошибочную запись. Итог считается автоматически, повтор периода запрещён. Записи прежних версий остаются «Без периода» до уточнения месяца. Фильтры показывают итоги только выбранных записей; карточка объекта и обзор суммируют все учтённые периоды. Сотрудник с expenses_view может только просматривать суммы.

## Откат выпуска через GitHub

Деплой готовит отдельный каталог, сохраняет текущий .env, фиксирует точный ID работающего образа и проверяет текущую версию. До переключения создаётся проверенная резервная копия. После переключения проверяются healthz, точное содержимое version.json и работа службы backup. Только после этого печатается RELEASE_VERIFIED.

При ошибке после переключения возвращаются образ и каталог предыдущего выпуска, проверяется его версия и печатается ROLLBACK_VERIFIED. Предыдущий каталог хранится в /opt/upravlenie-rollback/previous с ограниченными правами. Это откат кода; рабочая база и фотографии не перезаписываются. Выпуск 3.6.0 добавляет поля, совместимые с предыдущей версией. Будущие несовместимые миграции потребуют отдельного плана восстановления данных.

Сценарии успешного выпуска, сбоя запуска, неверной версии, остановленной службы копий и ошибки снимка проверяются tests/deploy.cjs на имитации Docker в отдельных каталогах. Рабочий сервер намеренно не ломается для проверки отката.
